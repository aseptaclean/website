# PART C — SCHEMA

One `@graph` per page. All `Service.provider` references point at the single existing
`LocalBusiness` `@id`. **No per-city LocalBusiness entities and no invented addresses** — one real
business, `areaServed` naming the cities.

**Service×city pages** — `Service` + `BreadcrumbList` + `FAQPage`

```json
{
  "@type": "Service",
  "@id": "{page_url}#service",
  "name": "Hoarding Cleanup in Mountain View",
  "serviceType": "Hoarding Cleanup",
  "url": "{page_url}",
  "provider": { "@id": "https://aseptaclean.com/#localbusiness" },
  "areaServed": {
    "@type": "City",
    "name": "Mountain View",
    "address": {
      "@type": "PostalAddress",
      "addressRegion": "CA",
      "addressCountry": "US"
    }
  },
  "description": "{meta_description}"
}
```

`FAQPage` carries the three FAQs from that page — **every question and answer must appear
verbatim in the rendered body**. Schema-only Q&A is a structured-data policy violation.

**City hubs** — `CollectionPage` + `BreadcrumbList`. No `Service` node; the hub isn't a service.

**Do not emit** `aggregateRating` (no reviews), `priceRange` (no published prices), or
`Organization.sameAs` until the profile URLs are in `.env.production`.

# PART D — BUILD SPEC

## D1. Route generation

One Astro template per type, driven by data. Do not hand-code nine routes.

```
src/pages/service-areas/[city]/index.astro          → 3 hubs
src/pages/service-areas/[city]/[service].astro      → 6 service×city pages
src/data/cityFacts.ts                               → verified facts, one record per fact
src/data/serviceCityPages.ts                        → the join records
```

Facts live once. The Mountain View 30-day permit fact is written once and referenced by three
pages, not retyped three times.

## D2. Fact record shape

```ts
type CityFact = {
  id: string;
  city: "mountain-view" | "sunnyvale" | "campbell";
  factType:
    | "franchise"
    | "permit"
    | "placement"
    | "sweeping"
    | "facility"
    | "moratorium"
    | "housing"
    | "parking";
  claim: string;          // verified fact only; do not mix inference into this field
  sourceName: string;
  sourceUrl: string;
  sourceType: "city" | "county" | "state" | "census" | "authorized-provider";
  verifiedAt: string;     // ISO date
  reviewAfter?: string;   // ISO date; recommended for rules/providers that can change
  appliesTo?: string[];   // service slugs; omit = all
};

type ServiceCityImplication = {
  id: string;
  city: CityFact["city"];
  service: string;
  heading: string;
  body: string;           // operational implication derived from one or more verified facts
  factIds: string[];      // every implication must point back to its supporting facts
};
```

`appliesTo` is the guard that stops Campbell's construction-debris rule from appearing on a
hoarding page.

## D3. Build-time guards — all must pass or the page ships noindex

> **Implemented 2026-08-21 as `scripts/city-seo-guards.mjs` (`npm run qa:seo`).** It runs against
> `dist/` after a production build and covers all eleven guards below, plus the schema and
> sitemap invariants in D4. Two severities: a **compliance** finding (guards 1–4, and a fact
> rendered on a service its `appliesTo` excludes) is an error on any built page, because
> `noindex` does not cure a sentence a visitor can still read; an **index-quality** finding on a
> `noindex` page is a publish blocker, which is this section's own remedy. See
> `docs/05-DECISIONS-LOG.md`, 2026-08-21, "The city-page indexation system closed".
>
> Guard 8 (8-gram Jaccard similarity) is the one item **not** implemented. The draft measured
> 0.127 worst-pair against a 0.85 block threshold, so it has no live decision to make; the nine
> pages are instead held apart by the uniqueness guard (9) on H1, title, and meta description,
> which is exact rather than statistical. Add the Jaccard pass before extending past these three
> cities, where shared openings start repeating across more siblings.

1. **Experience-claim guard.** Zero matches in rendered body: `we've`, `we have`, `our crews`,
   `in our experience`, `we regularly`, `most of our`, `years of`, `hundreds of`,
   `clients often`, `families usually`, `we (often|frequently|commonly|typically)
   (see|find|encounter|work)`.
2. **Claims guard.** Zero matches: `decontaminat`, `remediat`, `steriliz`, `sanitiz`,
   `biohazard`, `habitab`, `guarantee`, `licensed` (outside the footer negation), `certified`,
   `hoarder`, `gross filth`, `free assessment`.
3. **No public pricing / permit-fee guard.** Zero project-price `$` figures and zero permit-fee
   figures in rendered customer copy. Verified operational numbers — such as permit review time,
   clearance distances, parking limits, street-width restrictions, facility hours, and container
   sizes — are allowed.
4. **No hauling-claim guard.** Rendered copy must not state or imply that Aseptaclean transports
   customer debris off-site. Allowed concepts: on-site sorting, bagging, staging, clearing,
   loading into an approved container when included, dumpster coordination, disposal coordination,
   and coordination with the applicable authorized provider.
5. **Applicability guard.** Every rendered fact's `appliesTo` includes this page's service.
6. **Fact/implication separation guard.** Regulatory/provider facts must come from `CityFact`.
   Service-specific operational conclusions must come from `ServiceCityImplication` and reference
   supporting `factIds`.
7. **Freshness guard.** Every rendered fact has `verifiedAt`; any fact past `reviewAfter` blocks
   indexation until reverified.
8. **Similarity guard.** 8-gram Jaccard against every sibling. Warn above 0.75, block above 0.85.
   *(Current draft measures 0.127 worst-pair.)*
9. **Uniqueness.** H1, title, meta unique across all routes.
10. **Link guard.** Parent service link, city hub link, and at least one contextual inbound link
    present.
11. **Schema guard.** Every FAQPage question appears verbatim in the DOM.

## D4. Indexation

```ts
indexable =
  ownerConfirmedCityServed &&
  serviceIsActive &&
  allGuardsPass &&
  inboundLinkCount >= 1
```

Ship `noindex, follow` otherwise — not `nofollow`, and never canonicalized to the parent service
page. An unfinished local page is `noindex`, not a canonical pointer to somewhere else.

> **Implemented 2026-08-21 with three states, not two.** `src/data/publication.ts` defines
> `draft` | `noindex` | `published-index`. This section's binary treats "unfinished" and
> "finished but gated" as the same thing; they are not, and the difference is what a link may
> point at. A `draft` record produces **no route at all** — no HTML, no sitemap entry, and every
> link helper filters it out, so a page cannot be advertised before it is built. `noindex` is
> this section's state: built, reachable, `noindex, follow`, out of the sitemap.
>
> `sitemap.xml` derives the nine city routes from that one field, so the entry and the robots tag
> cannot be changed in separate commits. `inboundLinkCount >= 1` is enforced as *at least one
> inbound link from an indexable page* — a page reachable only from another gated draft has no
> crawl path. The self-referencing-canonical rule in the paragraph above is asserted against the
> built HTML on every run.

## D5. Measurement

Submit to Search Console on publish. Review at four and eight weeks:
impressions and clicks per route · queries per route · Google-selected canonical ·
"crawled – currently not indexed" · assessment requests by landing page.

don't saves you from building forty.
