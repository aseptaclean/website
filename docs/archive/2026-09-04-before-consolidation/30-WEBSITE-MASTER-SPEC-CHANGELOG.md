# ASEPTACLEAN MASTER WEBSITE STANDARD — V2 CHANGELOG

**Date:** August 24, 2026

> **HISTORICAL EXPLANATION ONLY — NOT IMPLEMENTATION AUTHORITY.** This file explains why the
> active standard changed. It cannot amend or override
> `docs/30-WEBSITE-MASTER-SPEC.md`, any verified fact, current owner decision, claims rule, or
> specifically locked canonical copy. Implementation agents must read the master itself.

This revision preserves the verified current-route/indexation inventory from the prior master and changes the target-state strategy, design governance, conversion system, and search operating rules.

## What changed

### 1. One primary customer now governs the conversion layer

The global site is now designed primarily for the adult child / family decision-maker managing an aging parent's or relative's difficult property.

The document explicitly separates:

- **one primary buyer / conversion system**, from
- **multiple legitimate SEO entry pages**.

This prevents the “one customer” strategy from accidentally destroying useful service-search architecture.

### 2. Homepage role was changed

The homepage is no longer treated as a broad generic brand/service directory.

It is now the primary family-decision-maker conversion experience, with the sequence:

- recognition;
- no need to know the service name;
- why ordinary service may not fit;
- process;
- what stays under client control;
- service routing;
- Project Notes / evidence;
- founder accountability;
- cost/scope context;
- fit / not-fit;
- FAQ;
- final CTA.

### 3. Primary CTA was changed

Visible primary CTA:

**Tell Us About the Property**

The existing `/request-assessment/` route can remain technically stable.

The form no longer begins by forcing the customer to choose a technical service category.

### 4. Risk reduction was rebuilt around procedural control

Added explicit trust-without-mature-proof architecture:

- Scope Control;
- Fit Before Sale;
- Belongings Control;
- Change Control;
- Finish Expectations;
- privacy / information handling.

The strategy avoids compensating for limited reviews with inflated claims or fake authority.

### 5. “Clinical Field Editorial” design direction was added

The visual system now combines:

- real field operation;
- editorial hierarchy;
- clinical/procedural discipline.

The design should feel calm, precise, private, serious, and human — not SaaS, luxury-for-luxury's-sake, maid-service, or theatrical hazmat.

### 6. Anti-AI rules were strengthened

AI is explicitly the implementer, not the art director.

The build contract now prevents AI from silently inventing:

- brand systems;
- fonts/colors/radii;
- claims;
- proof;
- locations;
- prices;
- services;
- photorealistic proof imagery;
- design patterns merely because they are common.

A mandatory post-build self-critique was added.

### 7. Typography and wrapping rules were substantially expanded

Added:

- heading line-count targets;
- `ch`-based display measures;
- `text-wrap: balance` / `text-wrap: pretty` guidance;
- anti-hyphenation / overflow rules;
- orphan/widow guidance;
- hard-break restrictions;
- correction order before shrinking type;
- viewport QA at 320, 360, 375, 390, 430, 768, 1024, 1280, and 1440px;
- 200% zoom QA.

### 8. Project Notes became the proof engine

The existing `/projects/` route can retain its URL, but the visible editorial concept is **Project Notes**.

Project Notes are structured around factual evidence:

- property/context;
- condition;
- constraint;
- approved scope;
- exclusions;
- approach/sequence;
- outcome/handoff;
- real media;
- related service/city.

### 9. Searchability became an operating system

Added explicit requirements for:

- crawlability;
- indexability;
- canonicals;
- XML sitemap;
- robots sitemap reference;
- Google Search Console;
- URL Inspection;
- Search performance monitoring;
- Google Business Profile alignment;
- service-area-business entity consistency;
- image SEO/performance;
- generative-AI Search visibility.

### 10. Google 2026 changes were reflected

The document now treats visible FAQs as useful content but no longer treats `FAQPage` schema as a Google rich-result growth tactic, reflecting Google's May 2026 FAQ rich-result deprecation.

The search strategy also incorporates Google's 2026 guidance favoring first-hand, non-commodity, people-first content rather than mass-produced query variants.

### 11. Build sequence changed

New order:

1. restore/stabilize;
2. homepage + request-assessment conversion endpoint;
3. decide whether a distinct family-property-cleanup page deserves to exist;
4. gold-standard Hoarding Cleanup San Jose page;
5. first six core service pages;
6. service-family hubs;
7. first city cluster;
8. Project Notes proof engine;
9. resources from real demand;
10. geographic expansion;
11. measurement/CRO loop.
